# KineTexture local release exporter

Python 3.10+; zero runtime dependencies. Public distribution and the particular
files' licensing remain subject to the project review. This tool copies only
explicit reviewed files and never publishes, runs Git, rewrites history or
deletes source material. It does not decide whether an input is legally reusable.
`build-requirements.txt` pins the tested offline wheel-build tools. Build in a
preprovisioned environment with `pip wheel --no-index --no-deps
--no-build-isolation .`. This round tested Windows CPython 3.12.4 only.

Manifest schema version 1 requires a `snapshot` metadata object and nonempty
`files` array. Every entry requires these fields:

```json
{
  "source": "relative/source.py",
  "destination": "src/package/module.py",
  "sha256": "64 lowercase hexadecimal characters",
  "owner": "verified owner or recorded contributor",
  "source_type": "original",
  "license": "Apache-2.0",
  "upstream_url": null,
  "upstream_revision": null,
  "notice": "",
  "review_status": "approved"
}
```

`source_type` is `original`, `generated` or `third_party`; third-party entries
must also identify an upstream URL and fixed revision. An `approved` value is
the caller's explicit review record, not an approval generated by this tool.
The exporter preserves additional metadata, including provenance evidence,
generator records, dependency revisions, source commit/dirty state, API/schema
versions and gate results. Generated files still require their own review.

`kinetexture-release export --source-root source --manifest release_allowlist.json --output new-candidate`
requires an existing source root/output parent and a nonexistent output. It
prevalidates the complete allowlist and source hashes before creating output.
Paths must be canonical POSIX relative file names; `.git`, absolute paths,
traversal, globs, Windows reserved names, symlinks, hardlinks, junctions/reparse
points, duplicate/case-colliding destinations and existing output are rejected.
The payload byte budget is 128 MiB. No broad directory is an implicit allowlist.

`kinetexture-release verify --output new-candidate` verifies exact file and
directory membership plus SHA256 against `release_receipt.json`. Extra files,
missing files, changed bytes and links are failures. The receipt embeds the
reviewed manifest and source-manifest hash; archive this receipt with a trusted
external archive hash. A mutable receipt alone is not an authenticity signature.

An OS write failure may leave a partial new directory for inspection; existing
targets and source files are never removed or overwritten. Concurrent hostile
filesystem replacement is outside this local tooling's threat model; do not
export into directories writable by an untrusted concurrent process.

## Complete local source preview

`prepare_preview.py` now treats its explicit `PREVIEW_FILES` list as a
build-completeness requirement, not an approval record. It includes the native
export adapters, synthetic tests, relocated installed consumers, standalone IK
example, documentation checker and this release-tool regression test. It never
globs directories, generates `approved` entries or refreshes a reviewer's hashes.

A reviewer supplies a frozen manifest at
`tools/kinetexture_release/reviewed_preview_manifest.json`, or selects another
path with `--manifest`. Every entry uses the base schema above and additionally
requires `reviewer` (a non-placeholder string) and `evidence` (a nonempty list of
source/review references). The top level requires
`preview_policy: "kinetexture.complete-source-preview/1"`. Its `snapshot` requires:

- `source_head`: the full 40-character commit containing the reviewed payload.
- `reviewer` and `review_evidence`: the reviewer and concrete source/review records.
- `public_distribution_authorized: false`: this workflow only makes a local candidate.

Source and destination paths must match the complete explicit file set exactly.
Missing or extra entries, pending/unknown approvals, missing review evidence,
changed bytes and unsafe paths fail before output creation. A source change
requires a new review of the changed bytes; the script cannot renew that review.
The manifest is outside its own payload. The copied script can therefore have a
fixed reviewed hash without a self-reference cycle. The receipt embeds the
complete supplied manifest and its SHA256; archive that digest independently.

The original `reviewed_preview_manifest.json` remains the frozen historical
record. The earlier maintained SDK/CLI documentation remains recorded in
`maintained_docs_manifest_20261101.json`. The source-maintenance projection uses
`maintained_source_manifest_20261104.json`, which additionally records the scoped
VMD interpolation fix and its two synthetic tests. Earlier manifests correctly
reject the maintained bytes rather than silently updating their recorded hashes.

Run these commands from the repository root. A new output label is required for
each candidate:

```powershell
python tools/kinetexture_release/prepare_preview.py --manifest tools/kinetexture_release/maintained_docs_repair_manifest_20261104.json --check
python tools/kinetexture_release/prepare_preview.py --manifest tools/kinetexture_release/maintained_docs_repair_manifest_20261104.json --output build/reviewed-source-preview
python -m unittest discover -s tools/kinetexture_release/tests -p test_preview_manifest.py -v
```

`--check` is read-only. `--output` can only create a new directory below this
checkout's `build/`. It does not build, install, deploy, publish, query Git,
change repository visibility or copy binary DLLs. No sibling allowlist/SBOM with
automatically approved current bytes is produced. The receipt preserves the
reviewer's metadata instead of inventing toolchain versions or runtime evidence.

Local source/provenance review and synthetic build validation may be performed
by an authorized agent. The review record must identify the actual reviewer and
evidence; these rules do not require a separate manual approval for each local
file. Public distribution remains a separate owner decision. See
[preview review scope](REVIEW_NOTICE.md) for exclusions and historical references.

The current documentation repair uses
`maintained_docs_repair_manifest_20261104.json`: an 80-file projection with
corrected root/installed READMEs and current manifest guides. The Chinese README
is frozen separately as staging metadata outside the fixed preview payload.
The earlier source manifest and all previous receipts remain unchanged.
